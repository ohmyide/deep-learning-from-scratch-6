# 第 1 章 · 分词器：文本怎样变成模型看得懂的数字

**本章产物**是一套合并规则、一个文本与 ID 的双向转换器，以及预训练用的 `codebot/tiny_codes.bin`。第 2 章的词表大小和第 3 章的训练标签都从这里来。先记住 ID 只是字典键，ID 100 并不比 ID 50 更重要。

## 1.1 字符级：起点是一张双向字典

对语料 `aba`，可以建 `{'a':0,'b':1}`，把 `aba` 写成 `[0,1,0]`，再用反向表复原。字符表可读，但遇到训练词表之外的汉字或 emoji 就要决定报错或用未知符号替代。字符还可能由多个 Unicode 码点拼成，人眼看到的单位和 Python 字符串索引也可能不同。先运行 `.venv/bin/python ch01/01_char_tokenizer.py`，找出字典建立、查表和还原三步。

## 1.2 字节级：用 256 个起始 ID 覆盖 UTF-8

`'A'.encode('utf-8')` 是一个字节；`'猫'` 需要三个，许多 emoji 需要四个。每个字节都能用 0～255 表示，所以新增字符也能编码。单个字节未必构成有效字符，解码要先把字节拼起来。字节法的代价是序列长，模型的上下文窗口以 token 计费。运行 [02_byte_tokenizer.py](02_byte_tokenizer.py)。

## 1.3 BPE 学习：把经常相邻的符号并成一个

假设一段字节 ID 是 `[97,98,97,98,99]`。相邻对 `(97,98)` 出现两次，可分配新 ID 256，然后把序列改成 `[256,256,99]`。接着重新统计，继续合并。真实流程在所有片段上统计，相等频次如何打破平局也会影响词表。只在合并时处理不重叠的匹配，例如 `aaa` 合并 `aa` 后还剩一个 `a`。先读 [03_bpe_train.py](03_bpe_train.py)，再画出第一轮的计数表。

## 1.4 编解码：训练看频率，使用看已学的顺序

编码新文本时，把它拆成字节，在当前相邻对中挑训练期最先学到的可用合并，直到停下来。词表固定后，编码时不能重新按当前句子统计频率决定优先次序。解码为 ID 对应的字节串拼接后统一 UTF-8 解码。调用 `decode(encode(text))` 验证往返，随后比较 token 数，二者分别验证正确性和压缩。对应 [04_bpe_tokenizer.py](04_bpe_tokenizer.py)。

## 1.5 特殊 token：正文之外的协议

`<|endoftext|>` 标记样本边界，也可以成为生成停止条件。训练时避免普通 BPE 跨过它，推理时让它作为单一 ID。它的 ID 与总词表一起决定模型配置，换词表就要重训或做显式迁移。注意 `pad`、`EOS` 与普通数字 ID 的含义由协议决定。对应 [05_special_token.py](05_special_token.py)。

## 1.6 预分词：让 BPE 在线段内合并

预分词先用正则把文本切成片段，再在每个片段内部跑 BPE。这限制了合并跨越哪些边界，保留空格、数字和标点等规律，也提供重复片段优化的机会。代码任务中缩进和换行有语义，清洗时要保留它们。GPT-2 风格正则对空白有专门分支；运行 [06_pretokenize.py](06_pretokenize.py) 看带空格的片段怎样打印。

## 1.7～1.9 从 TinyCodes 到训练样本

- **1.7** [07_tiny_codes.py](07_tiny_codes.py) 供训练领域词表，统一入口在 [codebot/tokenizer.py](../codebot/tokenizer.py)。先用已附带的 `merge_rules.pkl`，再研究如何训练新词表。只加载信任来源的 pickle。
- **1.8** [08_eval.py](08_eval.py) 对比词表与压缩。可用 `UTF-8 字节数 / token 数`，值越大表示每 token 平均覆盖更多字节。在代码、中文、英文各测同一批文本；压缩更好只说明序列更短。
- **1.9** [09_bpe_encode.py](09_bpe_encode.py) 把 IDs 写成 `uint16`，第 3 章必须用相同 dtype 读取。16 位无符号整数可容纳 0～65535。运行会写出训练文件，先保留仓库已有数据再做实验。

## 可运行实验

从仓库根目录运行。试着改输入再解释每种文本的 token 数。

```python
from codebot.tokenizer import BPETokenizer

tokenizer = BPETokenizer.load_from("codebot/merge_rules.pkl")
for text in ["def add(a, b):\n    return a+b", "猫🐈", "<|endoftext|>"]:
    ids = tokenizer.encode(text)
    assert tokenizer.decode(ids) == text
    print(len(text.encode("utf-8")), len(ids), ids[:12])
```

**过关标准**：能说明 Unicode、字节和 token 的区别，手算一次 BPE 合并，并解释同一句话为什么换词表后 ID 会变。第 4 章将复用算法，重点解决内存和运行时间。


## 加练 · 先分清训练与使用

把片段 `abab` 和 `ab` 当成两个词段。初始 `ab` 共三次，`ba` 一次。第一轮把 `ab` 合成 X 后，两个词段分别是 `XX` 与 `X`。第二轮若学到 `XX → Y`，新文本 `abab` 会依次走 `abab → XX → Y`。倒着查表可还原。现在只保留第一轮规则，生成的 ID 仍能解码，但模型要多读一个 token。

测真实数据时把训练词表用的文本与测压缩的文本分开。对同一段 Python，把四个空格换成制表符，再比较分词结果和往返校验。你改动的不仅是显示结果，还可能改变代码的语义。


## 对照 GPT-2：同样是字节级 BPE，也可能切出不同 ID

本书的预分词模式可以同 GPT-2 的编码器里面的正则逐项比较。可选前导空格让 `" cat"` 与 `"cat"` 能成为不同的预分词片段。两套实现即便都从 UTF-8 字节出发，只要编号、合并排名、训练语料、边界中的任一项不同，最终 ID 都可能不同。对模型来说，每个 ID 直接索引自己训练过的嵌入表，不能随意把另一套词表换进来。[GPT-2 原始编码器](https://github.com/openai/gpt-2/blob/master/src/encoder.py)

```python
from codebot.tokenizer import pretokenize, BPETokenizer

tokenizer = BPETokenizer.load_from("codebot/merge_rules.pkl")
for text in ("cat", " cat", "\n    return a + b", "猫🐈"):
    pieces = list(pretokenize(text))
    ids = tokenizer.encode(text)
    assert "".join(pieces) == text
    assert tokenizer.decode(ids) == text
    print(repr(text), pieces, ids)
```

看清三列的区别。第一列是原字符串，第二列是正则选出的片段，第三列才是 BPE 编码结果。拿到合并规则和二进制语料时应配套使用。作者的数据卡说明 TinyCodes 来自经过加工的 Python 代码集，并同时提供文本、token 二进制和生成它的合并规则。[作者数据卡](https://huggingface.co/datasets/koki0702/zero-llm-data)

**自检与答案**：为什么 1,000 词的 CodeBot 还能编码从未见过的汉字？它始终保留了 256 个基本字节，没学到更长合并时可以退回字节序列。代价通常是占用更多上下文 token。
