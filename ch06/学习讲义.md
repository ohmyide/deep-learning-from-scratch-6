# 第 6 章 · 训练 StoryBot：优化器、训练稳定性与偏好

## 6.1～6.2 SGD 到 AdamW

设一个参数为 `w=1`，梯度为 2，学习率为 0.1。SGD 一次变成 0.8。Momentum 保留过去梯度方向的移动平均，减少高频震荡。Adam 另外追踪梯度平方的移动平均，更新大致为 `lr * 一阶矩 / sqrt(二阶矩)`，使各参数调整步幅适应各自梯度尺度。初始化矩估计为零使早期偏小，除以 `1−β^t` 做偏差修正。AdamW 在梯度更新外对参数单独做衰减，避免衰减项被 Adam 的自适应分母重新缩放。读 [02_adamw.py](02_adamw.py)，注意结尾示范用的是 PyTorch 自带优化器，比较手写类时显式替换实例，并从同一初始参数起跑。

## 6.3 学习率日程：先让更新稳定，再逐渐减小步幅

Warmup 让开始几步从小步长逐步走到峰值。后续衰减有利于在较优区域精细调整。书里的 D2Z 在当前 [03_lr_scheduler.py](03_lr_scheduler.py) 表现为 warmup 后线性降到零。用总共 100 步、warmup 10 步手算第 0、10、55、100 步的倍率，分别为 0、1、0.5、0。训练变化要记录实际有效 batch、优化器和日程长度。

## 6.4 混合精度：表示范围与精确程度各有代价

FP16 指数范围小，太大的值会溢出，太小的值可能变零。BF16 指数范围接近 FP32，但尾数更短，同样会舍入掉很小的增量。混合精度让适合低精度的矩阵计算加速、节省内存，同时让敏感运算保留足够精度。FP16 训练常用梯度缩放，BF16 通常无需。硬件支持和后端影响收益。运行 [04_mixed_precision.py](04_mixed_precision.py)，观察舍入、下溢与溢出。CPU 能看数值效果，真实吞吐要在目标设备测。

## 6.5～6.6 预训练、验证与文本质量

[05_pretrain.py](05_pretrain.py) 对训练和验证 token 文件建只读 memmap，按需切 `x`、`y`。梯度范数裁剪在更新前压住少量异常大的步子。留出验证集，用 eval 模式计算交叉熵，避免把记住训练数据当作学会。困惑度是 `exp(loss)`，比较时固定 tokenizer 和数据。生成检查应覆盖人物一致、情节和结束，共用一批 prompt 与采样设置来比较两个模型。

[06_generate.py](06_generate.py) 负责生成，[07_llm_judge.py](07_llm_judge.py) 与 [09_llm_judge.py](09_llm_judge.py) 演示评审及成对比较。评估可固定模板，盲化模型名，交换 A/B，记录平局及人工复核样本，减少评委位置和文风偏好。可先用本地规则测格式、长度和重复率，再选择是否使用外部评委。这两个脚本默认含 API key 占位符，使用外部服务涉及凭据和调用费用。

## 6.7～6.8 RLHF 与 DPO

同一个开头可以接无数个故事，唯一标准答案不容易写，成对偏好比较较容易收集。Bradley–Terry 用 `sigmoid(好答案得分 − 差答案得分)` 表达偏好概率。经典 RLHF 路线先拟合偏好奖励，再用在线采样和强化学习优化策略，并约束离初始策略过远。

DPO 使用固定偏好对和参考策略，直接优化两种回答的相对 log 概率。分别计算当前/参考对 chosen/rejected 的序列 log 概率。先比较两答案在当前模型下的间隔，再减掉参考模型的间隔，最后用 `-logsigmoid(beta * Δ)` 作为损失。若当前等于参考，差值为 0，损失为约 0.693。把参考纳入比较可以扣除起点的既有偏好。训练无需每轮在线生成一组答案，代价是信号受固定偏好数据覆盖限制。

读 [08_dpo.py](08_dpo.py) 的 `DPODataset`、`get_sequence_logprobs`、`compute_dpo_loss`。重点看 prompt 和 padding 的 mask，以及参考模型的 no-grad。序列 log 概率是回答 token 的 log 概率求和。对不同长度的 chosen 和 rejected，应检查 mask、截断、有无 EOS；偏好评估也应分长度观察。读 [DPO 原论文](https://arxiv.org/abs/2305.18290)。

## 可运行实验 · 人工算一次 DPO

```python
import torch
import torch.nn.functional as F

current = torch.tensor([-3.0, -5.0], requires_grad=True)
reference = torch.tensor([-4.0, -5.0])
delta = (current[0] - current[1]) - (reference[0] - reference[1])
loss = -F.logsigmoid(0.1 * delta)
loss.backward()
print(round(loss.item(), 4), current.grad.tolist())
```

损失约 0.6444。chosen 项梯度为负，梯度下降会提高它的 log 概率，rejected 项方向相反。真实模型的两个 log 概率来自共享参数，更新会牵动整个分布。


## 加练 · 先建立统一的验证小表

挑三个故事开头，每个模型每个开头生成三次，固定训练集版本、temperature 与最大 token 数。每条给“是否跑题”“人物是否一致”“是否正常结尾”三列打分，再和验证损失并排看。若 DPO 之后偏好胜率上升而验证交叉熵也上升，原因可能是目标不同：偏好优化在重新分配回答概率。再检查是否因截断把前两个模型的大部分结尾都抹掉。关注生成长度能避免将更长自动误作更好。

读源码时还可用 `model.train()` 和 `model.eval()` 标记边界。验证阶段须避免参数更新，模型需固定权重进行比较。若你只换学习率日程，保持 tokenizer、数据、更新次数一致。


## 一次训练更新拆成四个可检查的部分

1. **输入对齐**。memmap 从 token 文件切出一段，后一位作为标签。
2. **前向与 loss**。用当前学习率、精度和模型计算预测误差。
3. **更新**。反传出梯度，必要时限制总范数，再交给 AdamW。
4. **验证**。隔一段更新，固定模型参数，在未训练过的数据上估计损失。

权重衰减和梯度裁剪作用不同。裁剪缩放当前梯度，限制异常大的一步。AdamW 的衰减额外收缩参数。最容易做的对照是把梯度设为 0，比较 AdamW 打开或关闭衰减时，参数是否仍会变化。[AdamW 原论文](https://arxiv.org/abs/1711.05101)

```python
import torch

for decay in (0.0, 0.2):
    w = torch.nn.Parameter(torch.tensor([2.0]))
    opt = torch.optim.AdamW([w], lr=0.1, weight_decay=decay)
    w.grad = torch.zeros_like(w)
    opt.step()
    print(decay, round(w.item(), 3))
```

结果为 2.0 和 1.96。这里特地给出全零梯度张量。若让梯度保持 `None`，PyTorch 可以跳过这个参数，实验含义会变。

### 怎样读 DPO 的训练曲线

如果初始策略与参考模型相同，则初始偏好 logit 为 0。这时损失约 0.693，只说明当前模型相对参考还未形成额外偏好。训练 loss 随后下降，要用留出对检查偏好能否泛化。故事质量还能分解为连贯性、语法与情节。使用自动评审时，记录评审版本、提示、平局与换位后的结果，先读几个实际故事再解释总分。[TinyStories 原论文](https://arxiv.org/abs/2305.07759) · [DPO 原论文](https://arxiv.org/abs/2305.18290)

**自检与答案**：两个模型使用不同词表，同一验证文本上 token 平均损失可直接比较吗？每个 token 覆盖的文字不同，应统一 tokenizer，或把对数似然换成可比的按字节计量。
