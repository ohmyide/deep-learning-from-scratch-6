# 第 2 章 · 模型：从 token ID 到下一 token 的分数

**本章产物**是一个可训练 GPT。输入 `ids[B,T]`，输出 `logits[B,T,V]`。`B` 是批量，`T` 是序列长度，`V` 是词表大小。每个位置的那一行分数都用于预测下一个 token。训练一次可以监督整个序列的许多位置。

## 2.1～2.3 注意力：把硬查表变成加权读取

- **2.1** 普通字典通过精确的 key 找一个 value。软字典允许查询同时接近多个 key，比如两个权重为 0.8 和 0.2，可返回 `0.8*v1 + 0.2*v2`。模型里查询 Q 表示当前位置想找的信息，K 表示每个位置可被匹配的特征，V 表示匹配成功后读取的内容。读 [01_soft_dict.py](01_soft_dict.py)。
- **2.2** `Q @ K.T` 为每个查询列出所有键的匹配分，逐行 softmax 把分数转为和为 1 的权重，再与 V 相乘。若 Q 是 `[T,D]`，K 是 `[T,D]`，分数就是 `[T,T]`。注意 softmax 沿键维度而非查询维度。读 [02_attn_math.py](02_attn_math.py)。
- **2.3** 点积把 D 项相加，若各项独立且方差约为 1，总体标准差约为 `sqrt(D)`。除以它使分数尺度更稳定，避免 softmax 很早变得近似独选，梯度难以调整。读 [03_attn_scaling.py](03_attn_scaling.py)，把 `[1,2,3]` 放大 100 倍观察 softmax。

## 2.4～2.6 顺序与遮挡

- **2.4** 词嵌入把 ID 查成向量，Transformer 块交替执行注意力和逐位置 FFN，末端投影回词表。注意力让各位置交换信息，FFN 改写单个位置已经聚合的特征。
- **2.5** 同一 token 出现在不同位置，词向量本身一样。位置编码提供顺序。可把按位置索引的向量加在词嵌入上，位置向量既可用确定函数生成，也可从任务中学习。CodeBot 使用可训练的绝对位置表，超出表长就需要改上下文策略。
- **2.6** 输入 `[我,喜欢,猫]` 对齐目标 `[喜欢,猫,EOS]`。若位置 0 注意到了位置 1，训练就提前看到了答案。因果遮罩把未来位置的分数设为负无穷，softmax 后权重为 0。它贯穿预训练、SFT 和生成。读 [06_attn_mask.py](06_attn_mask.py)。

## 2.7～2.10 从一个头到 GPT

- **2.7** 一个大投影矩阵可拆成两个较窄矩阵乘积。若中间宽度 r 小于模型宽度 D，使用两层 `D×r` 与 `r×D` 的参数，把参数量从 `D²` 变为 `2Dr`，同时限制可表达的矩阵秩。先把输入投影成低维 V，聚合后再投影回去，利用矩阵乘法结合律得到同一种思路。读 [07_attn_value.py](07_attn_value.py)。
- **2.8** 多头各自学习 Q/K/V 投影，可并行聚合不同线索。常见形状 `[B,H,T,Dh]`，每头独立算权重，拼接再投影。把每头的输出过各自投影后相加，等价于拼接后用一个拼成的大投影。读 [08_multi_head.py](08_multi_head.py)。
- **2.9** LayerNorm 在单个 token 的特征轴上减均值、按标准差缩放，并应用可学习的缩放和平移。FFN 用中间层扩张特征维度，再压回原宽度。穿过残差加法可以保留旧特征，优化器也有更直接的梯度路径。读 [09_norm_gelu.py](09_norm_gelu.py) 和 [Block](../codebot/model.py)。
- **2.10** [10_gpt2.py](10_gpt2.py) 和共享实现组合了位置嵌入、多个块及词表投影，并让输入嵌入共享输出权重。保存同时保留结构参数和权重，加载时须用匹配词表和结构。随机初始化模型的形状合理，能力要靠训练获得。

## 可运行实验 · 测试模型有没有偷看

```python
import torch
from codebot.model import GPT

torch.manual_seed(7)
model = GPT(16, 8, 32, 4, 1, 64, 0.0).eval()
with torch.no_grad():
    a = model(torch.tensor([[1, 2, 3, 4]]))
    b = model(torch.tensor([[1, 2, 9, 8]]))
print(a.shape)
torch.testing.assert_close(a[:, :2], b[:, :2])
print("共同前缀的输出相同")
```

预期 `[1,4,16]`，前两个位置的输出相同。第 3 章只需要把这些分数和正确的下一 token 对比。

## 框架对照：亲自走一遍 Q、K、V 和形状

原始 Transformer 论文研究翻译，使用编码器和解码器。本书的 GPT 用因果自注意力做续写。两者共享缩放点积的运算。对一条序列，`q @ k.T` 的行是查询位置，列是能被查询的位置。每行读出 V 的一份加权和。写成批量代码时，前面的 batch 和 head 维度可以保留不动。[Transformer 原论文](https://arxiv.org/abs/1706.03762)

```python
import math
import torch
import torch.nn.functional as F

q = k = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
v = torch.tensor([[10.0], [20.0]])
scores = q @ k.T / math.sqrt(q.size(-1))
future = torch.ones(2, 2, dtype=torch.bool).triu(1)
weights = scores.masked_fill(future, float("-inf")).softmax(dim=-1)
output = weights @ v
expected = F.scaled_dot_product_attention(q, k, v, is_causal=True)
torch.testing.assert_close(output, expected)
print(weights.round(decimals=3), output.round(decimals=3))
```

第一行的两个权重是 `[1,0]`，所以第一个位置只读到 10。第二行同时读到两项，聚合约为 16.70。再把 softmax 改成 `dim=0`，观察断言为什么失败。要保证每个查询读出的权重总和为 1，归一化轴应是 key。

**自检与答案**：如果把注意力层全部移除，同一个位置的 FFN 仍能得到前面 token 的信息吗？FFN 单独作用于各位置，跨位置依赖要从注意力等序列混合操作获得。
