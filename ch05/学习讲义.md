# 第 5 章 · 改良 GPT：位置、特征与生成速度

**本章产物**是 StoryBot 的模型骨架。第 2 章已经可以预测下一 token，本章用更常见的现代组件替换内部实现，外部仍是 `IDs → logits`。预训练权重和结构相关，不能直接把 CodeBot 权重装进 StoryBot。

## 5.1 RoPE：让注意力理解相对距离

旋转二维向量不会改变长度。若 Q、K 分别旋转 p、q 对应的角度，它们的点积主要由角度差决定。RoPE 把 head 向量分为二维子空间，在不同子空间使用不同频率，让 Q/K 的匹配随相对位置变化。V 仍用来传递内容。读 [01_rope.py](01_rope.py)，再找 [StoryBot 模型](../storybot/model.py) 的 `RoPE.forward(offset=...)`。解码追加 token 时，offset 要与缓存已有长度一致，位置不能从 0 重新开始。RoPE 允许讨论长度扩展，但直接将缓存尺寸加大不能保证任务质量。阅读 [RoFormer 论文](https://arxiv.org/abs/2104.09864)。

## 5.2 SwiGLU：让特征按输入动态通过

Swish/SiLU 是 `x*sigmoid(x)`，平滑调节输入强度。SwiGLU 做两份投影，一路经 SiLU 作为门控，逐元素乘另一路得到调制结果，再输出投影回模型宽度。与第 2 章 FFN 相比多一个投影，选择中间宽度时要同时看参数和计算。读 [02_swiglu.py](02_swiglu.py)。这里的门控是特征维度级的，第 8 章 MoE 的路由选择的是专家子网络。

## 5.3 RMSNorm 与结构取舍

RMSNorm 使用 `sqrt(mean(x²)+eps)` 缩放特征，保留均值方向，通常再乘学习的尺度。LayerNorm 还会先减均值。对 `[2,2]`，无仿射形式的 LayerNorm 输出约 `[0,0]`，RMSNorm 约为 `[1,1]`。看 [03_rmsnorm.py](03_rmsnorm.py)。

本书的改良结构去掉 dropout、若干线性层的偏置，输入嵌入和输出投影分别学习。Dropout 取舍依赖数据规模与过拟合风险。取消权重共享给两端更独立的表达能力，同时多占一份词表矩阵内存。变化应该用同等预算的验证结果比较。

## 5.4 组成改良 GPT

[04_improved_gpt.py](04_improved_gpt.py) 中每块依次做“归一化 → 注意力 → 残差”和“归一化 → FFN → 残差”。读模型配置、权重初始化、最后的 logits 与保存加载。预归一化让每个子层接收受控尺度的输入，残差主路径保持畅通。运行前向先看 `[B,T,V]`，再进行真实训练。

## 5.5 KV 缓存：不要一遍遍投影已经读过的 token

**Prefill** 一次处理整个提示，缓存所有层对应的 K/V。**Decode** 每次只为新 token 计算新的 Q/K/V，新 Q 再读历史与当前 K/V。缓存节省重复投影和过去位置的处理，请求越长，缓存本身越占内存。启动新请求要清空缓存。带缓存的代码通常假定 prefill 后每次只提交一个 token；多 token 追加需要按绝对位置处理因果掩码。读 [05_kvcache.py](05_kvcache.py) 和 [生成工具](../storybot/utils.py)。

## 可运行实验 · 缓存与完整前向等价

```python
import torch
from storybot.model import GPT

torch.manual_seed(7)
model = GPT(32, 16, 32, 4, 1, 64).eval()
ids = torch.tensor([[1, 2, 3, 4]])
with torch.inference_mode():
    expected = model(ids)[:, -1]
    model.clear_cache()
    model(ids[:, :3], use_cache=True)
    actual = model(ids[:, 3:], use_cache=True)[:, -1]
    model.clear_cache()
torch.testing.assert_close(actual, expected, atol=1e-6, rtol=1e-4)
print("最后位置 logits 一致", tuple(actual.shape))
```

先验证等价，再测速。生成时开启缓存与否应该改变运行方式，合理误差内的模型输出应该一致。


## 加练 · 把代码和代价对上

取层数 4、批量 1、长度 256、KV 头数 16、头维 32。如果 K/V 用 BF16，每元素 2 字节，不考虑额外管理开销，缓存约为 `2 × 4 × 1 × 256 × 16 × 32 × 2` 字节，即 2 MiB。上下文扩大十倍，缓存字节也约十倍。看代码继续回答：缓存按哪一轴拼接，RoPE 读取哪一段位置。第 8 章会通过减少 KV 头数降低这笔成本。


## 识别三件互不相同的改进

用一个训练批次追踪三条线。RoPE 在每层注意力里随位置旋转 Q、K，改变位置之间怎样匹配。SwiGLU 在同一位置内调节哪些特征通过。RMSNorm 控制送入子层的数值尺度。它们的分工分别是**位置关系、特征变换、数值尺度**。代码中把每个模块替回基础版时，先确定它改变的是位置、FFN 还是归一化。同一项改动还可能改变参数量，公平比较应记录预算。[GLU 变体](https://arxiv.org/abs/2002.05202) · [RMSNorm](https://arxiv.org/abs/1910.07467)

两个二维向量若旋转相同角度，点积保持不变。若分别转过不同角度，它们的夹角会随位置差改变。RoPE 利用这个性质。以公式记忆，令 `R(p)` 表示位置 p 的旋转，`R(p)Q` 与 `R(q)K` 的点积可以等效为固定 Q，只让 K 转过 `q-p` 的角度。调试带缓存的实现时，可以在完整前向与增量前向中打印当前位置，验证它们指向同一个角度表。

### 从单次推理到批量服务

本书的做法足以解释单条请求。服务系统中每个请求的长度不同，缓存也不断增长和释放。PagedAttention 的思路是把 K/V 按块管理，减少连续预留和浪费。第 8 章的 GQA 压缩的是每个 token 的 K/V 头数，而分块管理关注怎么安置许多请求。两者可以叠加。[PagedAttention 论文](https://arxiv.org/abs/2309.06180)

**自检与答案**：新会话为什么要清空旧缓存？它是上一个前缀的 K/V 内容与位置记录，继续使用会让新输入读到无关旧内容、位置也错位。
