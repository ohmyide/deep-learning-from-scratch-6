## 从一次补全开始

你在编辑器里输入 `return a +`。语言模型先把输入转成 token ID，然后为每个候选下一 token 算一个概率。它可能给 ` b` 0.75，给 ` 1` 0.10，把余下 0.15 分给其他候选。选中 ` b` 后，把它追加到前缀，在更长的前缀上重新预测。只要重复，就能生成一段程序。整个句子的概率按条件概率相乘。假设产生 ` b` 的概率是 0.75，而在追加它后产生换行的概率是 0.80，那么连续生成这两个 token 的概率就是 0.60。

模型怎样知道 ` b` 应该排得靠前？训练给模型看大量前缀及其真实下一 token。每猜错一次，损失告诉模型当时给真答案的概率有多低。优化器根据梯度调整参数，逐渐让训练数据里更常见或更符合上下文的结果获得更高概率。

## 三种训练信号分别从哪里来

| 阶段 | 一条数据长什么样 | 学到什么 | 本书在哪里用 |
|---|---|---|---|
| 预训练 | `def ... return a + b` | 给定前缀续写。标签直接来自原文右移 | 三个项目都用 |
| SFT | 指令「实现加法」和示范回答 | 给定指令时模仿示范响应，重点监督回答部分 | CodeBot |
| 在线奖励训练 | 一道加法题、模型生成的多条答案、每条得分 | 提高得分较好的响应的相对概率 | CodeBot 的 GRPO |
| 离线偏好训练 | 同一开头、较好的故事、较差的故事 | 相对参考模型提高被偏好答案的优势 | StoryBot 的 DPO |

“训练模型”改变权重。“调用模型”读取权重并生成。温度和采样规则会改变本次选词方式，参数本身保持固定。区分这两件事，才能定位生成效果变化来自数据、参数还是解码设置。

## 在 Python 里做最小语言模型

下面只数两项相邻符号的频率。为便于手算，把 `a`、`+`、`b` 分别当成一个符号。

```python
from collections import Counter, defaultdict

corpus = [["a", "+", "b"], ["a", "+", "b"], ["x", "+", "c"]]
counts = defaultdict(Counter)
for tokens in corpus:
    for previous, next_token in zip(tokens, tokens[1:]):
        counts[previous][next_token] += 1

next_counts = counts["+"]
total = sum(next_counts.values())
probs = {token: count / total for token, count in next_counts.items()}
print(probs)
print("选择最高概率:", max(probs, key=probs.get))
```

输出中 `b` 概率为 `2/3`，`c` 为 `1/3`。问自己：输入 `a +` 与 `x +`，这个程序会给不同答案吗？它只记得最后一个符号 `+`，所以两次预测相同。Transformer 的注意力允许当前 token 结合更早的上下文，这是第 2 章要解决的问题。换成真实文本时，还需要第 1 章确定符号划分规则。

## 读全书时追踪五样东西

1. **文本**从哪个数据文件来。
2. **ID**由哪套 tokenizer 转换，训练与生成是否同一套。
3. **预测分数**来自模型哪个时间位置。
4. **学习信号**来自真实下一个 token、示范答案、成对偏好还是奖励。
5. **产物**保存在哪里，下一步读取什么。
