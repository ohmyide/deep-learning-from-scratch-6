# 第 3 章 · 学习：训练 CodeBot，再让它按指令回答

**本章产物**依次是基础模型、指令模型、经过奖励优化的模型。它们可以用同一 GPT 架构，区别在数据、训练信号和权重。先在本机跑 [迷你 CodeBot](../小实验/codebot_cpu.py)，再读默认长跑脚本。

## 3.1 预训练：下一 token 的错题本

滑动窗口从 `[10,20,30,40]` 取 `x=[10,20,30]`、`y=[20,30,40]`。每个位置给 V 个 logits，交叉熵计算实际标签的 `-log p(y)`。真值概率从 0.1 提到 0.5，单项损失约从 2.30 降到 0.69。批量损失反向传播产生梯度，优化器更新权重。均匀猜测时损失约为 `log(V)`，可作为判断起点的参照。看 [01_pretrain.py](01_pretrain.py) 的 `TokenDataset`、batch、模型和 loss。它默认 20,000 次更新，并保存 `codebot/model_pretrain.pt`。脚本会选 CUDA、Apple MPS 或 CPU。

## 3.2 生成：同一个预测动作重复执行

生成只读取最后位置的 logits，抽一个 token 接在末尾再计算。温度 T 将 logits 除以 T，较大让分布更平，greedy 是直接挑最高分。Top-k 保留 K 个最高候选，Top-p 按概率从高到低保留达到累计阈值的最短前缀，随后重新归一化。前者固定数量，后者随置信度变化。仓库 [02_generate.py](02_generate.py) 主线演示温度；[通用生成器](../codebot/utils.py) 支持温度 0 的 greedy 和结束 token 停止。推理用 `eval()` 关 dropout，用 `no_grad()` 省反传开销。

## 3.3～3.4 SFT：教模型收到问题后怎么回答

`instruction` 与 `response` 用 Alpaca 风格的标题串起来，尾部放结束符。模板使模型能区分指令与回答。输入仍然带着完整问题，损失主要落在回答 token，填充位置同样不记损失。注意区分**注意力遮罩**（能看谁）和**损失遮罩**（哪个答案打分）。`x`、下一 token 标签和 mask 必须同时对齐，首个回答 token 由其前一个位置预测。批内短样本补齐才好组成矩阵，丢掉 padding 的损失才不会教模型生成填充符。

依次看 [03_alpaca.py](03_alpaca.py)、[03_sft.py](03_sft.py)、[04_chat.py](04_chat.py)。训练和对话的标题、换行及结束符要匹配。打开对话后用一组未见过的问题核对，算术偶尔成功不代表稳定会算。

## 3.5～3.6 强化学习和策略梯度

状态是当前文本前缀，动作是抽到的下一 token，策略是当前 token 的分布。整段回答是轨迹。奖励可以在回答结束后才产生。书的脚本用最后一个解析出的整数是否等于加法答案作为 0/1 奖励。它检查答案，无法检查推导质量。

训练希望提高平均奖励。把“所有可能答案的概率 × 奖励”求导，利用 `∇p = p∇log p`，再用实际抽样替代全枚举，就会出现 `回报 × ∇log π(动作|状态)`。动作由抽样产生，梯度通过已选 token 的 log 概率传播。高奖励响应通常被增加概率。抽得少会有噪声，这就是需要基线的原因。

## 3.7～3.9 基线、剪切与 GRPO

- **3.7** 同一题生成一组回答，比较每条的奖励与组平均。奖励 `[0,1,0,1]` 得优势 `[-0.5,0.5,-0.5,0.5]`。难题全错、易题全对时，这个组提供的相对学习信号为 0。本仓库取 `reward-mean`；DeepSeekMath 论文包含另外的归一化以及参考策略 KL。不同变体的长度归约方式也会影响训练。
- **3.8** 当回答来自旧策略，新旧模型概率比 `r=πnew/πold` 可近似修正分布差异。完整轨迹比值随长度相乘会很不稳定，脚本使用 token 级比值加剪切。目标取 `min(r*A, clamp(r)*A)`，使有利方向的大幅变化不会继续带来同等收益。剪切目标并不保证所有概率比实际都在范围内。
- **3.9** [09_grpo.py](09_grpo.py) 看 `generate_group` → `compute_probs` → `grpo_loss` → 同组生成数据重复更新。旧策略是采样策略快照，DPO 下一部分里的固定参考模型有不同职责。脚本的定期准确率遍历同一批可用于训练的 81 道加法题。若要看泛化，应另留未见题并同时记录奖励、输出长度、独立题集正确率，分辨“找到更好的答案”和“更擅长讨好奖励规则”。

## 可运行实验 · 对齐转移目标和回答掩码

```python
ids = [10, 11, 20, 21, 99, 0]  # 提示、回答、EOS、padding
x, y = ids[:-1], ids[1:]
mask = [0, 1, 1, 1, 0]
print(list(zip(x, y, mask)))
assert [target for target, use in zip(y, mask) if use] == [20, 21, 99]
```

前缀仍是模型输入。请指出哪个位置预测 20。如果误把 mask 左移一位，会监督到 prompt 并可能丢掉 EOS。进阶阅读可对照 [DeepSeekMath](https://arxiv.org/abs/2402.03300) 与 [Dr. GRPO 分析](https://arxiv.org/abs/2503.20783)。


## 加练 · 只更新回答，以及剪切为什么取最小值

SFT 源码把不打分的标签写成 `-100`，交叉熵默认忽略它们。以下是一个最小例子。由回答触发的梯度仍会经由注意力传到早期位置的参数路径。

```python
import torch
import torch.nn.functional as F

logits = torch.zeros(2, 5, requires_grad=True)
labels = torch.tensor([-100, 2])
loss = F.cross_entropy(logits, labels)
loss.backward()
print(round(loss.item(), 4), logits.grad.tolist())
assert not logits.grad[0].any()
```

损失约为 1.6094，只有第二行 logits 直接得到监督。回到代码看这里两行相当于展平后的两个位置。

GRPO 中若 `A=0.5`、`r=1.4`、剪切范围为 ±0.2，目标取 0.7 与 0.6 较小的 0.6。若 `A=-0.5`、`r=0.6`，目标取 -0.3 与 -0.4 中较小的 -0.4。这给出两种有利方向被截住的例子。当前实现把 token 目标求和再除以响应数，对更长的回答会累计更多项。对本书练习，先核对评分函数对末尾整数的处理，再对照 [Dr. GRPO 研究](https://arxiv.org/abs/2503.20783) 区别不同长度实现的行为。


## 把四种学习信号放在同一个问题上

拿「3 + 4 等于多少」做对照。预训练在原文 `3+4=7` 里逐位置猜下一 token。SFT 用含指令和示范回答的模板，指令作为上下文而回答负责计算损失。GRPO 先让模型尝试多条答案，再按是否等于 7 给分。若用第 6 章 DPO，则提供一对固定回答如「7」和「8」，训练比较相对偏好。架构可以相同，训练时拿来打分的数据不同。

公开的指令训练工作将人工示范、偏好比较与策略更新用于不同步骤。本书反映了同样的数据与目标分工，并用短代码演示对应机制。[InstructGPT 论文](https://arxiv.org/abs/2203.02155)

### 采样时到底剪掉哪些 token

```python
import torch

p = torch.tensor([0.58, 0.26, 0.11, 0.05])
ids = p.argsort(descending=True)
top_k_ids = ids[:3]
ranked = p[ids]
top_p_ids = ids[(ranked.cumsum(0) - ranked) < 0.80]
print("top-k:", top_k_ids.tolist(), "top-p:", top_p_ids.tolist())
```

Top-k 固定保留前三项。Top-p 保留第一、第二项，累计达到 0.84，随后从保留项重新归一化并抽样。第二项虽然让总和大于阈值，仍需保留才能够到阈值。阅读时可用它补充本地以温度为主的生成脚本。训练对话的标题和换行属于输入格式。现代对话库同样用模板把角色和消息渲染为模型预期的 token 顺序。[Hugging Face 对话模板说明](https://huggingface.co/docs/transformers/main/chat_templating)

**自检与答案**：一条生成回答中多数 token 来自高分响应，却仍出现低分回答的某些字，这正常吗？这里的奖励按整段回答给出，无法直接判断哪个 token 导致得分。第一个排查点是评分规则和采样策略，再看 mask 与概率比。
